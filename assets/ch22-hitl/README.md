# 第 22 章：人工审批执行链

- `approval-execution.svg`：章内静态插图，由交互查看器原生 SVG 导出，自动适配浅色／深色主题。
- `approval-execution.html`：独立交互查看器，支持缩放、查找、主题切换和图片导出。
- `approval-execution.architecture.json`：Archify 源规格；使用 architecture 渲染器表达审批流程，保留中文节点的可读尺寸。
- `verification.json`：产物字节摘要、自动校验和人工视觉检查记录。

阅读顺序：上排从左向右，到人工审阅后向下，再沿中排从右向左进入执行。编辑分支创建新 revision，旧批准失效，新版本重新进入审批；图内卡片补充了这条返回路径。拒绝或过期关闭当前审批，不产生新的业务副作用。执行前任何校验失败均须停止；图中仅画出通过路径，不能把未画出的失败分支理解为自动放行。

已保存派发意图但没有确定回执时，保留稳定 `operation_id` 并先只读核实。核实发现原操作完成，保存原回执；缺乏确定事实时保持未知，交由受控人工处置。人工批准和业务成功是两种不同事实。
