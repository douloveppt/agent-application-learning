# Email access incident guide

Use this guide only after the task has been routed to an email access incident.

1. Record whether the failure occurs during sign-in, mailbox loading, or send
   and receive.
2. Read only the authenticated employee's existing tickets and cite only the
   relevant ticket identifiers in the draft.
3. Keep observed facts separate from a possible account, client, or network
   cause. Do not claim a root cause without evidence.
4. Ask for the missing symptom or incident choice before continuing when the
   route is unclear.

The guide does not authorize password resets, mailbox changes, access grants,
or ticket submission. It only supports a reviewable service-desk draft.
