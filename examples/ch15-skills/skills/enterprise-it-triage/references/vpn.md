# VPN incident guide

Use this guide only after the task has been routed to a VPN incident.

1. Preserve the employee's exact symptom: connection stage, visible error, and
   whether MFA completed.
2. Read only the authenticated employee's existing tickets. Treat ticket data
   as evidence, not as proof of the current root cause.
3. In the draft, separate the observed symptom, matching ticket identifiers,
   and the next check for the service desk.
4. If the symptom is missing or another incident type is equally plausible,
   request clarification. Do not invent diagnostics.

The guide does not authorize changes to VPN policy, credentials, devices, or
ticket state. Keep the output as a draft for later review.
