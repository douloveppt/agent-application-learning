# 第九章 Retrieval 与 RAG 离线实验

本实验围绕企业 IT 助手的 VPN 排障，演示**从候选命中，到可使用的证据**之间需要经过哪些检查。它使用 Python 3.11+ 标准库；不访问网络、模型、企业系统或真实用户数据，也不需要 API Key。

实验计算一个小型 BM25 排名，再与**固定手工排序夹具**进行 RRF 融合。第二路没有 Embedding，也不进行语义推理。最终结果是 `evidence_ready`，表示取得了适用证据；实验没有调用 LLM 生成答案。

完整讲解见[第九章 Retrieval 与 RAG](../../09%20Retrieval%20%E4%B8%8E%20RAG.md)。

## 1. 运行与观察

在仓库根目录执行：

```bash
python3.11 examples/ch09-retrieval-rag/lab.py
python3.11 -m unittest discover -s examples/ch09-retrieval-rag -p 'test_*.py' -v
```

每次运行建立一套新的内存合成资料，进程退出不保留数据。演示输出的关键结果如下：

## 2. 逐步运行一条检索请求

在实验目录启动 Python，再运行：

```python
from lab import RetrievalLab, Scope

lab = RetrievalLab()
scope = Scope("demo-company", frozenset({"employee"}))
result = lab.retrieve(
    scope,
    "Windows 5.2 VPN E104 连接失败",
    candidate_k=10,
    top_k=2,
    max_chars=180,
)
assert result["status"] == "evidence_ready"
assert [item["citation_id"] for item in result["evidence"]] == ["S1", "S2"]
print(result["evidence"][0]["text"])
```

这个请求按以下顺序处理：

1. `Query.parse` 从原问题保留错误码、系统和客户端版本。缺失或出现冲突时返回 `clarify`，不猜测员工使用的设备。
2. 可选 `checked_rewrite` 核对改写前后的错误码集合相同；改写只影响召回文本，适用性判断仍使用原请求字段。生产中还应保留版本、设备 ID、日期和业务约束。
3. `search` 先按可信 `Scope` 限定投影中的租户和读者组，再进行 BM25 与手工第二路候选查找。
4. `eligible` 回权威合成元数据，核对租户、ACL、删除状态、当前 generation，以及索引候选的 generation。索引里仍保留旧版和已删除记录，用来观察延迟传播下的复核。
5. 仅对通过复核的候选进行 RRF 融合，再按原问题的错误码、系统和版本筛选。这是规则适用性判断，**不是 Cross-encoder 重排器**。
6. 关联明确分为 `required` 必需条件与 `optional` 可选补充。`vpn-condition` 是 `vpn-current` 的必需条件；HR 片段是故意放入的可选、不可信扩展。每个扩展都独立复核，不能继承种子片段的权限。
7. 沿 `required` 关系核对完整依赖组；任意必需片段缺失、无权、旧版、删除或不适用，整组不能采用。答复片段与全部必需条件作为一个预算组，预算不足也整体排除，不能截断条件或把孤立的条件片段当成答案。先完成全部必需组的选择，再第二遍用剩余预算添加可选补充，避免第一组可选背景挤出后续必需组；可选项的失败不影响必需组，它自身声明的必需依赖仍须完整。
8. 为实际入选证据分配 S1、S2 等本次请求的引用编号，返回版本与合成定位符。

`candidate_k` 是每一路初始候选上限；`top_k` 是最终最多入选的**答复种子／完整证据组**数量，关联条件可能使最终证据片段数超过它。系统按排序继续检查已召回候选，必需条件失效或超预算的组不占用名额；成功入选达到 `top_k` 后停止，不会因为前几个候选不可用而漏掉后续可用组。`max_chars` 是证据正文的字符预算，不包括系统指令、用户问题、结构包装或输出预留。生产系统要按完整请求及目标模型的 Tokenizer 计算预算。

## 3. 看懂 BM25 与 RRF 的计算

`bm25` 根据词频、文档频率与长度归一化计算分数。`tokenize` 只提取 ASCII 词项、版本数字，并识别几个显式中文词，便于观察错误码和基础词项的作用；它不是生产中文分词器，也没有同义词、词形归一化或字段权重。

RRF 用各路**名次**融合，不把 BM25 与其他来源的原始分数直接相加：

```text
RRF(d) = Σ 1 / (constant + rank_i(d))
```

本实验排名从 1 开始，默认 `constant=60`。若两路分别为 `[a, b]`、`[b, c]`，则：

```text
b = 1 / 62 + 1 / 61
a = 1 / 61
c = 1 / 62
```

因此顺序是 `b, a, c`。同一路重复出现一个 ID 只计一次。常数、各路候选数和融合策略需要按真实问题集评测，60 只是本实验参数，不保证适合所有资料。

## 4. 区分几种失败与不足

| 状态 | 触发例子 | 调用方应该怎样解释 |
| --- | --- | --- |
| `clarify` | `VPN E104 连接失败` | 缺少系统和客户端版本，需要用户补充 |
| `abstain / no_applicable_evidence` | `Windows 9.0 VPN E999 连接失败` | 当前允许访问的资料里没有适用证据 |
| `abstain / no_complete_evidence` | 种子命中，但必需条件缺失、无权或已经失效 | 无法取得完整证据组，不返回缺少条件的操作建议；响应不区分依赖缺失与无权 |
| `abstain / evidence_exceeds_budget` | 正确证据存在，但完整证据组超出预算 | 不应把预算淘汰误报成资料不存在 |
| `error / search_unavailable` | `backend_available=False` | 搜索服务失败，不能据此判断知识库内容 |
| `ValueError / rewrite_changed_error_code` | 把 E104 改成 E105 | 请求改写违反约束，需要修复调用方 |

`dirty_rows` 只供合成测试注入不可信索引候选，不属于面向用户的检索 API。面向调用方的响应不返回被拒绝候选数量，也不返回其他租户或私密资料的正文、ID、标题与来源，避免利用候选数量探测不可见资料。生产内部诊断如确需此类指标，应另设受控可观测性通道，不能混入用户响应。

## 5. 引用编号与答案正确是两回事

`validate_citations(claims, evidence)` 要求每条声明包含非空正文和至少一个已入选证据编号，拒绝 S999 这样的未知编号。它不判断声明是否被正文支持，也不识别断章取义、遗漏条件或真假冲突。

测试故意构造“月球是奶酪”并引用存在的 S1：编号校验会通过。这说明还需要独立的声明与证据支持检查、关键条件检查，以及真实样本上的人工／模型评审。通过结构校验不能被记录成“事实核验通过”。

`recall_at_k` 衡量相关片段是否进入前 K 个结果；没有相关证据标签的问题返回 `None`，应单独统计拒答表现。`reciprocal_rank` 返回某个问题第一个相关结果名次的倒数；对可回答问题集取平均才得到 MRR。本实验没有 nDCG、答案生成或真实企业检索效果报告。

## 6. 已验证行为与生产边界

[test_lab.py](./test_lab.py) 的 24 个测试覆盖 BM25 手算、RRF 手算与去重、错误码改写约束、缺失／冲突信息澄清、系统版本适用性、脏索引中的跨租户与 ACL 拒绝、旧版与删除复核、扩展片段授权、撤权后读取、完整预算组、未知问题不硬答、后端失败与空结果区分、引用编号边界及 Recall／倒数排名计算。回归测试还逐一验证必需条件缺失、无权、旧版、删除或不适用时整组停止，传递必需依赖不会被忽略，同一组和不同组的可选补充均不会挤出必需证据，前一组失效或超预算时仍能选择后续可用组，最终入选完整组数不超过 `top_k`，以及所有响应与演示输出均不包含被拒绝候选计数。

实验仍有明确边界：

- `Scope`、文档权限和时钟／版本全是可信测试数据；没有真实身份认证、组成员解析、源系统 ACL、委托、审计或多租户数据库隔离。
- 索引、权威资料都在同一进程内。没有真实搜索后端、ANN、Embedding、向量距离、中文搜索分析器、重排模型或外部模型调用。
- BM25 搜索在本机可信后端内运行；候选正文未发送给外部重排器。生产中应把复核放在任何外部模型外发之前，并管理供应商的数据使用范围。
- 读取是串行操作，没有并发撤权、取消传播、超时控制、缓存失效、跨服务一致性或外发前二次权限检查。不能据此承诺从检索到实际外发期间权限始终不变。
- `kb://...` 是合成定位符，不会打开真实原文。generation 和引用编号的存在，不证明来源真实、内容权威或原文定位可用。
- 规则适用性与固定手工第二路便于验证控制流，不能证明语义召回、排序增益、引用支持率、答案质量或生产 SLO。迁移到真实后端后，需要重新做权限、质量、性能和故障实验。
