# 第 32 章实验：数据用途、派生谱系、删除传播与反馈准入

这个实验用**内存中的合成资产目录**演练数据治理的几个关键控制：有服务权限不代表有训练权限；删除需要沿派生谱系传播；保留例外和既有模型必须如实报告；反馈需要经过绑定内容和证据的可信审核，才能进入评测集。

它只使用 Python 3.11+ 标准库，不联网、不读取真实文件或工单、不调用模型，也不产生物理删除。示例中的租户、来源、审核者、保留例外和用途许可都是教学配置，不是对真实主体的授权或法律判断。

## 运行

在项目根目录执行：

```bash
python3.11 examples/ch32-data-governance/lab.py demo
python3.11 -m unittest discover -s examples/ch32-data-governance -p 'test_*.py' -v
```

演示只向标准输出打印 JSON，不创建文件。`expected_rejections` 中的拒绝是预期结果，成功运行退出码为 `0`。

## 1. 先观察用途和租户边界

`TrustedRegistry.grants` 按 `(tenant, source_locator)` 记录允许的用途。`tenant-a` 的合成来源同时允许 `service`、`evaluation`、`training`；`tenant-b` 的同名来源只允许 `service`。两份原文的文字完全一样，但这是两个不同租户的数据资产。

因此，`b-source` 可以派生业务缓存，却不能进入 `train_manifest`。即使另一个租户的文字相同、已经获准训练，也不能借用它的许可。这里没有用内容摘要代替数据身份或租户范围。

原始来源可以在可信注册表明确授予的多个用途下使用；来源首次以 `service` 登记，并不覆盖或替代注册表中的其他独立用途许可。因此 `a-source` 可以分别直接生成评测样例和训练清单。**每个派生版本则绑定单一用途**：评测样例不能作为服务回答读取或重新包成服务缓存，训练清单不能用于服务，服务缓存也不能因为根来源另有训练许可就自动升级成训练材料。读取和再次派生都会检查当前资产及沿途所有非来源祖先的用途；新的用途需要从仍获准的原始来源重新构建，并走对应准入流程。

`Catalog.admit()` 还要求派生资产有完整父节点，并拒绝未知父节点、跨租户边、复用资产 ID、自己指向自己或缺少来源的记录。新节点必须在父节点之后加入，且不能覆盖既有 ID，因此公开准入 API 无法创建环；读取时的递归检查还会发现被模拟存储损坏引入的环。

## 2. 沿谱系删除，并阻断迟到数据

示例把原文、记忆、索引、缓存、评测样例、训练清单和模型标记都登记为资产。每个派生资产保存不可变父节点 ID；删除目标为精确的 `(tenant, source_locator)`，覆盖该来源所有已登记版本及其可达后代。

`Catalog.delete(request_id, tenant, source_locator)` 首先写入来源 tombstone，再处理已知副本。新版本即使使用全新的资产 ID，也会因来源被撤回而拒绝；旧节点也不能继续派生新缓存。即使来源还没来得及入库，先到达的删除请求仍可写入 tombstone，阻断之后的迟到导入。

| 资产情况 | 教学处理 | 能否视为已经解决 |
| --- | --- | --- |
| 原文、记忆、索引、缓存、评测样例 | `state=deleted`，`payload=None` | 只在内存目录模拟范围内解决 |
| 训练清单 | `state=blocked`，清空行成员载荷 | 阻断该清单后续使用；不代表抹除已训练模型 |
| 教学保留例外 | `state=held`，保留内容，禁止普通读取 | 未解决；回执为 `partial` |
| 既有模型标记 | `state=review_required`，禁止普通使用 | 未解决；必须单独评估处置 |

删除返回的 `assets` 逐项列出状态，`unresolved` 列出保留例外和模型问题。使用同一请求 ID、同一范围重试可以恢复任务；复用同一请求 ID 更换租户或来源会被拒绝。

两个来源混合生成一个摘要时，撤回其中一个来源会保守地删除整个摘要。实验不尝试从摘要里“减去几句话”。真实系统若需要保留其他来源的合法内容，应从仍可使用的来源重新生成，并登记新的版本与谱系。

## 3. 保留例外释放后，模型问题仍然存在

演示先对 `a-source` 设置一个**教学保留例外**，再执行删除。首次回执的关键结果是：

```json
{
  "status": "partial",
  "assets": {
    "a-source": "held",
    "a-memory": "deleted",
    "a-index": "deleted",
    "a-cache": "deleted",
    "a-train": "blocked",
    "a-model": "review_required",
    "eval:tenant-a:fb-1": "deleted"
  },
  "unresolved": ["a-model", "a-source"]
}
```

可信操作方释放 `a-source` 的保留例外后，用同一删除请求重试。原文被置为 `deleted`，但 `a-model` 仍在 `unresolved` 中，整体依旧为 `partial`。

这是刻意保留的未完成状态。训练清单被撤回，并不会自动改变模型权重。真实项目需要根据数据、风险和适用要求，评估停用、替换、重新训练或经过验证的其他处置；目录标记和一轮测试无法证明模型已经忘记某条数据。本实验没有实现机器遗忘。

如果构建不含模型、也没有保留例外的实验目录，删除可返回 `complete_in_simulated_catalog`。这个名称明确限定为**已登记的内存目录**，不表示某个真实企业的全部数据和备份都已经清除。

## 4. 用户点赞或模型自评不会成为审核授权

`Feedback.self_reported_reviewed` 是不可信输入。把它设为 `True`，不能越过 `publish_eval()`。

可信审核保存在 `TrustedRegistry.reviews`，按租户和反馈 ID 查找。审核必须同时满足：

1. `decision=verified`，审核方式为 `human_with_evidence` 或 `program_with_evidence`；模型自评不能作为这个示例中的准入方法。
2. 有审核者标识，且审核指向的证据与当前反馈一致。
3. 审核绑定当前反馈的完整摘要；更换输入、预期答案、来源或证据后，旧审核失效。
4. 来源当前仍然可使用，并且拥有 `evaluation` 用途许可。审核通过不自动扩展数据用途。

只有这样才会生成包含输入、预期答案、证据引用和反馈摘要的 `eval` 资产。直接用通用 `admit()` 导入新 `eval` 也会被拒绝，必须走审核入口。

这里的摘要只用于绑定版本，不是匿名化手段，也不能证明审核者真的看过可靠证据。真实系统还要实现审核者身份与权限、证据真实性、脱敏效果、标注规范、双人复核或争议仲裁、审计记录与评测集访问隔离。

## 主要接口

| 接口 | 职责 |
| --- | --- |
| `TrustedRegistry(grants, reviews, legal_holds)` | 安装由可信控制面提供的教学策略快照 |
| `TrustedRegistry.install_hold()` / `release_hold()` | 模拟可信操作方设置或释放保留例外 |
| `Catalog.admit(asset)` | 校验租户、用途、来源、谱系与撤回状态后登记资产 |
| `Catalog.read(tenant, asset_id, purpose)` | 检查根来源的当前用途许可、各级派生资产用途及祖先状态，拒绝用途升级、撤回或隔离内容 |
| `Catalog.publish_eval(feedback)` | 验证可信审核、内容摘要、证据和用途后发布评测样例 |
| `Catalog.delete(request_id, tenant, source_locator)` | 先阻断再传播，返回逐项状态和未解决项 |
| `fixture(with_model=True, held=True)` | 创建两个租户和一组可调故障条件的合成目录 |
| `demo()` | 输出五类预期拒绝、两次删除回执与其他租户仍可读取的结果 |

## 测试与工程边界

25 项测试覆盖用途不足、派生资产被跨用途读取或重新包装、服务派生物升级训练材料、获独立许可的来源直接生成评测与训练材料、未知来源、谱系缺失、跨租户边和读取、ID 覆盖、自环与损坏环、用途伪装、全图删除、迟到版本和派生、先删除后入库、保留例外及恢复、模型未解决、请求重放和范围冲突、混合来源摘要、不可信审核标记、模型自评、直接导入绕过、审核后改答案或证据、审核通过但用途不足、审核租户绑定与重复发布。

`tenant` 参数、策略注册表、审核记录和 hold 管理在实验中都假设由可信调用方提供。Python 对象的私有命名不是权限边界；本实验没有真实认证、多租户数据库行级隔离、凭据保护、策略签名、审批服务或抵御同进程恶意代码的能力。

此外，实验是单进程、同步、内存实现，没有持久化事务、并发删除锁、任务租约、失败重试调度、分布式增量水位或存储适配器回执。进程退出后资产与 tombstone 都会丢失。生产实现需要持久化撤回账本，并在导入、索引写入、缓存命中、训练取数与恢复备份之前检查它，避免因并发或重启使数据重新出现。

实验也不实现个人信息识别、匿名化证明、真实授权依据核验、保留期限计算、对象存储版本清除、向量数据库 compaction、缓存集群失效、日志与备份清理、外部供应商删除、法务审批或真实模型重训。`payload=None` 只是演示状态变化；谱系中的来源引用与最小审计元数据仍会保留，也需要自己的访问、保留和删除规则。
