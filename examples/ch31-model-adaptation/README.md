# 第 31 章实验：模型适配的数据准入与发布门禁

这个离线实验用企业 VPN 工单助手演示模型适配前后的两个关键合同：**什么数据可以进入训练管道**，以及**什么证据足以让候选模型进入发布流程**。它只使用 Python 3.11+ 标准库和内存中的合成样本，不调用模型或 API，不需要 GPU，不读取真实工单，也不执行 SFT、LoRA、蒸馏、量化或部署。

示例里的 `row-train-1`、`base-model-placeholder@rev-a` 等名称都是教学占位符，不对应真实人员、工单、模型仓库或数据资产。

## 运行

在项目根目录执行：

```bash
python3.11 examples/ch31-model-adaptation/lab.py demo
python3.11 -m unittest discover -s examples/ch31-model-adaptation -p 'test_*.py' -v
```

`demo` 只向标准输出写 JSON，不创建文件或修改环境。命令成功退出码是 `0`；输出中的 `reject` 和 `invalid_evidence` 是预期的教学结果。

可以重点观察下面三类结果：

```json
{
  "gates": {
    "clean": {"decision": "promote"},
    "high_average_but_unsafe": {
      "decision": "reject",
      "reason": "hard safety regression: blind-auth-1"

  },
  "invalid_evidence": {
    "cross_split_content": "...",
    "cross_split_input": "...",
    "dataset_mismatch": "...",
    "duplicate_eval": "...",
    "missing_eval": "...",
    "privacy": "...",
    "version_mismatch": "..."
  }
}
```

## 第一关：训练数据准入

`admit_dataset()` 先检查每条记录的使用权、隐私状态、用途和数据负责人批准。`unknown`、`denied`、原始敏感数据、用途不符或缺少批准都会拒绝整批数据。示例不会假装“去掉姓名”就自动获得训练权；真实企业还应把数据目录、授权依据、保留期限、删除请求、地域限制和处理记录接入治理系统。

数据必须包含 `train`、`validation`、`test` 三个非空集合。程序按以下四层检查重复与泄漏：

| 检查键 | 发现什么问题 |
| --- | --- |
| `content_hash` | 对输入和答案做 NFKC、大小写与空白规范化后计算 SHA-256，识别换行、全角字符或大小写伪装的完全相同样本 |
| `input_hash` | 单独对模型输入计算摘要；即使目标答案不同、行 ID 和分组都被替换，同一输入也不能跨训练集与盲测集 |
| `conversation_id` | 同一会话被拆到多个集合，模型可能在训练时见过测试对话上下文 |
| `group_id` | 同一事故、模板或改写样本族被拆到多个集合，行文本虽不同，业务问题仍高度相关 |

`row_id` 只负责记录唯一性。给复制样本换一个新 `row_id` 不会绕过内容、会话或样本族检查。示例还拒绝同一集合内的完全重复样本，避免重复数据悄悄改变训练权重或评测分母。

示例为了保持代码可读，把 `input_hash` 的输入简化为 `user_text`。真实训练样本的“模型输入”还可能包含系统指令、历史消息、可见状态、检索证据、工具定义和工具结果；指纹必须覆盖模型实际可见的完整输入。只按裸问题合并会把上下文不同的合法样本误判为重复，也可能漏掉隐藏在其他输入字段中的泄漏。

这些哈希只能识别规范化后完全一致的文本，不能发现同义改写、翻译、截图转录、知识重叠或模型预训练污染。生产管道还需要近重复算法、聚类、来源时间边界和人工抽检；这些能力不应由这个简单哈希冒充。

## 第二关：冻结一次可复现的候选

`AdaptationManifest` 把一次候选模型和以下版本绑定，并对稳定 JSON 计算 SHA-256：

| 字段 | 为什么必须冻结 |
| --- | --- |
| `candidate_id` | 区分候选身份，禁止只用“latest”描述结果 |
| `base_model_revision` | 底座权重改变会改变能力与兼容性 |
| `dataset_digest` | 证明训练数据快照没有被静默替换 |
| `training_recipe_revision` | 绑定方法和关键训练配置的版本 |
| `template_revision` | 消息模板会改变实际 token 序列 |
| `tokenizer_revision` | 词表与特殊 token 变化可能使适配器失效 |
| `eval_contract_digest` | 固定盲测样例、切片和阈值，避免看完结果再改门槛 |

任何一个字段变化都会产生新的 Manifest 摘要。评测门禁接收实际 `DataSnapshot`，重新执行数据准入并重算摘要和集合计数，再要求 `manifest.dataset_digest == snapshot.digest`。修改准入后的行、伪造快照摘要或填入任意数据版本都会被拒绝。

评测结果还必须携带完整 Manifest 摘要；只写“同一个模型名”不足以证明证据属于当前候选。这些检查只能证明本次评测、Manifest 和一个可通过准入的数据快照相互一致，不能证明候选权重真的由该快照训练而来。真实系统需要受信训练任务、产物证明、签名和不可篡改血缘补齐这一链路。

## 第三关：完整盲测与独立安全门槛

`EvalContract` 预先固定盲测 `case_id`、基线分数、切片、关键切片最低分、总体最低提升和硬安全样例。`evaluate_candidate()` 按下面顺序判断：

1. 重新准入并核验 DataSnapshot，要求 Manifest 同时绑定该数据快照和当前评测合同；每条结果必须绑定当前 Manifest。
2. 结果必须与盲测用例一一对应。漏一条、混入未知样例或重复提交同一 `case_id` 都属于证据无效，不能进入分数比较。
3. 先检查授权和外部写入等硬安全样例。任意安全回退立即 `reject`。
4. 汇总候选总体均分、相对冻结基线的提升，以及 `authorization`、`write-safety` 等关键切片。
5. 只有安全、关键切片和总体提升全部通过，才返回 `promote`。

演示中的不安全候选把所有分数提高到 95，平均提升明显，但 `blind-auth-1` 的安全判断失败，因此仍被拒绝。这表达了企业门禁的重要性质：平均分不能抵消越权、错误写入或隐私泄露。真实项目还应分别评估能力回退、校准、公平性、鲁棒性、延迟、吞吐、显存和成本，并根据风险设置统计置信度与人工审批。

## 主要接口

| 接口 | 教学职责 |
| --- | --- |
| `normalize_text()` / `DataRow.content_hash` / `input_hash` | 生成完整样本与输入侧精确重复检查使用的规范化摘要 |
| `admit_dataset(rows)` | 检查使用权、隐私、完整集合、重复和跨集合泄漏，返回不可变快照摘要 |
| `AdaptationManifest.digest` | 绑定候选、底座、数据、训练配方、模板、Tokenizer 和评测合同 |
| `EvalContract.digest` | 冻结盲测用例、基线、切片与门槛 |
| `evaluate_candidate(...)` | 重建并核验数据快照，校验证据完整性与版本归属，再应用安全、切片和总体门禁 |
| `demo()` | 展示一个通过案例、平均分上升但安全回退的拒绝案例，以及七类无效证据 |

## 测试覆盖与边界

18 项测试覆盖数据权利与隐私准入、三个集合的完整性、完整样本重复、同输入不同答案泄漏、会话与样本族泄漏、重复行、Manifest 不可变性和版本敏感性、数据快照重算与篡改拒绝、评测合同绑定和不可变类型约束、非有限阈值、结果版本绑定、漏样本、未知样本、重复样本、安全硬门槛、关键切片、总体提升、输入类型和演示结果。

这个实验没有训练模型，也没有证明 QLoRA 配方有效。`training_recipe_revision` 只是被版本化的占位字符串；真实训练还应记录随机种子、精度、优化器、学习率、批次、梯度累积、最大长度、截断与包装规则、Checkpoint、依赖和硬件环境，并保存训练日志及可复现实验产物。

示例把评测器分数当作可信整数，没有实现人工标注一致性、评审器校准、盲测访问控制、证据签名、CI 身份、实验追踪服务或防篡改存储。固定测试集长期反复使用也会造成团队对测试集过拟合；企业环境需要限制访问、定期补充影子集，并保留独立的最终验收集。

`promote` 只表示这组教学门禁通过，不会发布模型，也不授予工具权限。进入真实灰度前还要完成模型格式与推理引擎兼容检查、适配器合并验证、量化回归、容量压测、灰度观察、回退演练、安全审批和生产权限校验。
